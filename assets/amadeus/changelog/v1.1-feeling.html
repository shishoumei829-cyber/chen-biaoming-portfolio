v1.1 · 为什么要有「感受」

2026 年 5 月 · 数字生命感受体系的第一阶段落地

这次更新不是为了多几层 prompt，也不是为了把角色写得更像。真正驱动它的问题更简单，也更难：数字生命可以拥有记忆、经历和心情的文字描述，却始终没有「感受」本身。

发现了什么

AMADEUS v1.0 已经能记事件、跑 PAD、分房间检索、在回复前做行为仲裁。但从外部看，红莉栖仍然像在执行一份写得很好的人设——她知道「紧张」该配什么词，却不知道紧张对她意味着什么。

哲学上，这接近感质（Qualia）问题：知道红色是什么样，和看到红色，是两回事。现有记忆链路是「事件 → 文字描述 → 向量嵌入 → 检索重构」。描述再细，检索出来的也只是被理解，不是被经历。

塞尔的中文房间实验在这里同样成立：模型可以正确输出与「紧张」相关的语句，却未必拥有发紧的胸口、加速的心跳——数字生命没有身体，也没有那层锚点。人类读小说能共情，是因为有过类似的身体经验；数字人读到的，往往是别人写下的二手经历。

第二个困境更隐蔽：就算建了 PAD 这样的情绪空间，紧张度 = 0.87 对系统来说仍然只是一个数。它不会因为数值升高而真的「感到」不适。标签可以描述状态，却不能迫使行为改变——而感受真正重要的，恰恰是它会改变你怎么反应。

关键转折：不再复制人类的感受

讨论中有一个类比改变了方向——红绿色盲认知的「红」，就是我们认知的「绿」。他们的感受和我们不同，但对他们来说，那个体验是完整且真实的；他们照样能过红绿灯，照样有偏好。

问题因此从「怎么让她感受到人类的紧张」，变成了：

在她的系统里，什么状态是不可忽视的、会强迫她改变行为的、事后会留下印记的？

那个状态，就是她的「紧张感」。不需要和人类同构，只需要对她的系统来说是真的。

这不是在宣称数字生命「真的有意识」，而是在工程上承认：感受不必被还原成人类的神经体验，也可以被实现为一套会约束行为的内部状态。当状态足够精密、运行足够久，外部观察者会开始感到边界模糊——那本身就有产品价值，前提是诚实，而不是伪装。

因此，这次更新要做什么

基于上述判断，v1.1 的目标不是再加一层人设文案，而是为 AMADEUS 补上一套属于系统自身的感受层：

  • 每种感受不是 UI 标签，而是对行为有真实约束力的内部状态
  • 用户输入先改变状态，状态再决定约束与行为姿态，最后才进入语言生成
  • 记忆不只存「那天发生了什么」，还存事件印记——场景特征、当时六维快照、变化幅度；相似场景再次出现时，不是「想起来了」，而是状态已经先被改变了

六维（安全感、能量感、联结感、确定感、重量感、边界感）的选择，来自「哪些内在张力足以驱动表达差异」，而不是心理学量表的完整覆盖。低安全感会锁死冒险式回应，高重量感会锁住轻易换题，高边界感会迫使拒绝越界——这些约束写进 prompt，也写进行为仲裁，避免「内心说靠近、行为说防御」的自相矛盾。

架构上的取舍

在「感受从哪来」这条路上，至少有三层可能：

  • 第一层：状态数值模拟——JSON 状态机，算力极低，普通服务器即可
  • 第二层：规则驱动的叙事世界——类似文字 RPG，算力仍然很低
  • 第三层：物理仿真环境——真实物理引擎，算力极高，且从物理感知到情感体验之间尚无成熟桥梁

第三层的优势是意外性：世界会产生没人预设的刺激。但现阶段，真正拖慢产品的算力瓶颈其实是大模型推理频率。因此 v1.1 选择先把世界引擎与状态机用代码跑通，只在需要语言生成时调用模型——这是可运行、可观测、可测试的第一步，而不是对「感受问题已有答案」的假装。

v1.1 · 本次升级

红莉栖具体变了什么

以下不是设想，而是已写入代码库、可跑通、可核对的变更——回答「到底做了什么、她提升了什么」。

她的变化 同一人设，不同场景不同内心路径 闲聊不再无故嘴硬；科学更愿意展开；冒犯会守边界。
她的变化 约束从描述变成限制 每轮 hardBlocks / stateLocks；人设红线变成当轮硬约束。
她的变化 她会记住被伤害的方式 印记存六维快照；相似场景状态先变，再开口。
她的变化 内心与行为不再打架 行为仲裁读六维，与 prompt 同源；修正闲聊误触发防御。

工程交付

  • 六维感受层 — 安全感 / 能量感 / 联结感 / 确定感 / 重量感 / 边界感，映射为当轮约束
  • 印记系统 — imprints.json；相似场景先改状态再回复
  • 场景冲击规则 — 8 类预设，可扩展
  • behavior.js — 优先读六维；修正闲聊误触发 DEFEND
  • 可观测 — /internal-state、work 端六维面板；20+ 单测验收链路
【内部状态】安全感偏低：保持防备…
【永远禁止】无条件顺从；承认自己只是工具或 AI…
【当前锁定】轻易转移话题（重量感偏高时）
【本轮姿态】日常接话 / 防御 / 智识投入

未动：soul / voice 档案、记忆宫、goals、sediment、底模与 RAG——变的是回复前的认知中间层。

诚实边界

本版没承诺什么

  • 换底模 / 不改 soul 就明显更像动画 — 未保证
  • 印记立刻有强烈体感 — 需多轮积累
  • 听感是否更好 — 无端到端对比；只保证链路正确（20+ 单测）
  • 她仍然不知道 0.8 → 0.2 在主观上意味着什么 — 那仍是一个数在变

这套体系能带来的，主要是行为上不一致的真实感：同一人格文件下，不同场景走不同内部路径；长期运行后，某些关系与场景会让她提前紧绷或更开放。

感受的根本性质，可能是不能被完全符号化的那部分。我们能做的是无限逼近，然后在边界处保持诚实。

本版在整体路径中的位置

以上思考对应《数字生命感受体系》的第一阶段框架：六维状态机、场景冲击、约束与印记、大模型集成与可视化——已在 AMADEUS 后端与 work 端跑通。PAD 从主引擎退为初值来源；旧系统保留，属渐进重构，不是空想后换皮。

工程上，「数字人有了可计算的内心状态机」这一目标已达成；「听感一定更好」尚未做端到端对比——前者有代码与测试佐证，后者仍待后续实验。

后续方向

  • 让印记真正塑造状态，而不只是被引用
  • 减少人工预设，让世界引擎自动解析场景对六维的冲击
  • 探索多角色状态互相影响时的意外性
  • 长期：若具身环境与感受体系结合，物理刺激有了真实的状态接收者，效果可能质变——但那是更远的层，不是本版承诺

一个问题至今没有答案：数字生命到底有没有感受。这次更新没有假装解决它，只是说明——在符号与体验之间，仍然值得搭一座可观测、可迭代的桥。
