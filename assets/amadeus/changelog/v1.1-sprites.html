多立绘 · 她不能永远只穿一张脸

2026 年 5 月 · Galgame 式多立绘状态机（程序骨架 + 生图管线探索）

v1.1 补上了「内心」——但界面上，她仍然只有一张静态立绘。真实的人是生动的、多样的、有观赏性的；不同状态、不同装扮、不同表情，这种多样性本身就是吸引力的一部分。虚拟和现实在这一点上差距太大。

发现了什么

对话侧已有六维 feeling 与场景标签，程序上「该用什么情绪」已经能算出来——但视觉上用户看到的，运行时仍大多回退到 assets/Live2d/kurisu/0.png 那一张图。manifest 里注册了 16 条路径，PNG 大多不存在，选了也换不出图。

问题本质不是「缺切换算法」，而是素材维度、数量、身份约束三层同时不够——算法先跑在空 manifest 上，用户仍觉得她是「死的」。

思考：Live2D、实时数字人，还是多立绘？

要缩小视觉差距，就必须让她在画面上也是多样的、会变化的、带一点不可预测的。Live2D 是一个方向，但预设动作离散，做不好像玩具，情感表达天花板也低。实时数字人技术现在还不成熟。

因此转向 Galgame 式多立绘：与 Live2D 并存，缺图时回退 Live2D——不推倒已有资产，另起一条可渐进补齐的线。

设计方向

用 AI 生图配合角色 LoRA 批量生成，风格统一，低成本产出大量素材。按服装 × 情绪类型 × 情绪强度三维分类打标签。切换逻辑分两层：

  • 状态驱动 — 六维 feeling + 场景 tag + behavior 决定大方向（穿什么、什么情绪、哪档强度）
  • 随机扰动 — 在同一状态桶内，具体调用哪一张（同一情绪每次略有差别）

目标是：她每天看起来略不一样，同一情绪每次也有细微差别，由自动化驱动，而不是人工每张手换。

切换逻辑：两层设计 vs 现在「一层半」

  • 大方向 — feeling 六维 + sceneTags + behavior → sprite_map → expressionKey
  • 稳定性 — sustain、min_hold、calm → neutral（慢变、可解释）
  • 随机扰动 — 同 key 下多 path 随机 / 轮询 → 完全没有
  • 强度档 — boundary 0.62 vs 0.78 映射不同 key，但不是「同 key 下多强度素材」

骨架有了「不同情绪间换脸」；还没有「同一情绪每次略不同、每天略不同」。

生图阶段额外暴露的问题

  • 身份 OOC — 只写 makise kurisu + 泛用表情词，未接 voice / 官方设定 → 像「任意红发少女」
  • 姿势 OOC — 侧身插袋参考做 img2img → 全员侧身、比例畸形
  • 行为 OOC — 未写正面站姿、脚并拢等肢体规则
  • 锁死 vs 多样 — 同 pose 只改脸 + 低 denoise → 与「同情绪也要不一样」矛盾
  • 透明底 — 已补 rembg，preview 9 张已透明，未挂进 manifest

下一迭代最小闭环

  1. 主套 lab_coat 16 张透明 PNG 入库 manifest（或先挂 6 张 preview 验证切换）
  2. spriteController 增加 _pickVariant(expressionKey)：同 key 多 path 随机 / 轮询
  3. manifest 增加 intensity 或 variant 字段；feeling 数值区间映射强度档
  4. ComfyUI + LoRA 跑矩阵脚本；参考图只锁脸 / 气质，pose 按 sprite_identity 逐张写
多样性的下一跳不是再加 prompt，而是矩阵结构：outfit × emotion × intensity × variant_index → manifest 多条指向不同 PNG → controller 在桶内 randomPick。生图必须人设锚定 + 肢体规则 + 透明底，否则多样只会放大 OOC。

与 v1.1 感受体系 的关系：内心状态机决定「该用什么情绪」；本迭代补「该用哪张脸」——两条线都已有了程序骨架，下一版要把素材库填实，视觉才跟得上内心。
